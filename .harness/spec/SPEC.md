## 1. 软件功能

TraceDiary 是面向个人的轻量日记应用，核心目标是快速记录、稳定保存、方便回看。

- 今天：打开即写当天记录；默认展示周历，可一键展开为月历；周/月历均支持切换日期、补写历史日期；点击月份文字可跳到指定月份，再次点击底部“今天”返回当天；纯文本编辑、自动保存、云同步状态提示；当天页下方展示该日期的往年记录入口；编辑卡片菜单提供"清空当日内容"用于删除该日期记录（同步删除云端对象）。
- 回顾：按"AI搜索 / 搜索 / 年度总结"三个子页组织历史内容，默认进入 AI搜索。
  - 搜索：按关键词、年份、有记录日期等条件查找历史记录；有关键词时，结果卡片摘要围绕首个命中位置展示前后文，正文被省略的一侧显示省略号，摘要内所有可见命中使用主题主色并加粗。
  - AI搜索：通过端侧语义索引与用户配置的云端只读 Agent 查询历史记录、年度总结、本地统计和普通偏好；回答必须提供可验证的日期与原文证据。
  - 年度总结：查看和撰写每年的年度总结正文，不承载统计图表。
- 统计：展示记录数据概览，包括本月记录、连续记录、全年记录、月度趋势、年度热力图。
- 设置：提供数据加密、云同步、AI 搜索配置、数据导入、导出备份、提醒设置、日历每周第一天偏好、关于应用等入口。

非目标：不提供开放式 AI 工作台、写入型 Agent、无证据回答或本地生成式大模型；不暴露 Gitee、Token、仓库、分支、pull/push 等底层同步术语；不规划深色模式作为首版目标。

## 2. UI 设计风格

整体参考 OPPO / ColorOS 系统工具类应用：浅色背景、灰白分层、柔和阴影、克制圆角、深墨绿色作为主强调色。界面应保持安静、实用、低装饰感，避免营销页、纸质手账、强隐私保险箱或 AI 工作台气质。

- 四个一级页面不重复显示“今天、回顾、统计、设置”大标题，直接从各自首个功能区域开始；设置等二级页面仍保留返回按钮和页面标题。
- 回顾页二级分段固定为：AI搜索、搜索、年度总结；使用无胶囊背景的等宽文字 Tab，选中项使用主题主色和底部指示线，默认进入 AI搜索。

- “往年今日”不作为独立页面，只作为今天页或搜索结果的局部内容。

## 3. 技术栈

当前项目基础：

- Android Gradle Plugin 9.2.1
- Kotlin 2.2.10
- Jetpack Compose + Material 3
- minSdk 26，targetSdk 36，compileSdk 36.1
- 单模块结构：`:app`

规划选型：

- UI：Jetpack Compose、Material 3、自定义主题与组件封装。
- 本地存储：Room + SQLCipher 或等价加密数据库方案。
- 偏好设置：DataStore。
- 后台任务：WorkManager，用于自动同步与备份。
- 网络：OkHttp，用于对象存储同步、Embedding 模型下载和 OpenAI Chat Completions 兼容 Agent 调用。
- 序列化：kotlinx.serialization。
- 端侧向量模型：固定使用 INT8 ONNX 版 `BAAI/bge-small-zh-v1.5`，通过 ONNX Runtime Android 推理。

## 4. 架构设计

采用单 App 模块内的分层架构，首版不拆多模块，保持实现简单。

- UI 层：Compose 页面、导航、状态展示；只处理交互和渲染。
- ViewModel 层：维护页面状态、处理用户动作、触发用例。
- Domain 层：定义日记、年度总结、AI 检索、同步、导入导出的业务用例。
- Data 层：封装本地数据库、AI 加密索引、端侧模型、Agent 客户端、设置、文件导入导出和云同步客户端。

建议包结构：

```text
com.tracediary.app
  ui/
    today/
    review/
    stats/
    settings/
    security/
    ai/
    components/
    theme/
  domain/
    model/
    repository/
    usecase/
  data/
    local/
    sync/
    backup/
    security/
    settings/
    ai/
```

同步原则：

- 本地数据库是主数据源。
- 云同步只展示产品化状态，例如“已保存 · 云同步完成”。
- 同步配置放在设置页，不在主界面暴露对象存储实现细节。

AI 原则：

- 本地不运行具备推理与工具决策能力的 Agent；本地协调器只负责解锁门禁、向量检索、白名单工具执行、云端往返、证据验证和会话清理。
- 云端 Agent 只读取本地工具明确返回的数据，不能直接访问数据库、文件系统、应用密码、密钥或写接口。
- 关键词搜索与 AI 搜索相互独立；AI 不可用不得影响离线关键词搜索。

## 5. 数据结构

核心实体：

```kotlin
data class DiaryEntry(
    val date: LocalDate,
    val content: String,
    val createdAt: Instant,
    val updatedAt: Instant,
    val syncState: SyncState
)

data class AnnualSummary(
    val year: Int,
    val content: String,
    val createdAt: Instant,
    val updatedAt: Instant,
    val syncState: SyncState
)

data class SyncMetadata(
    val objectKey: String,
    val localUpdatedAt: Instant,
    val remoteUpdatedAt: Instant?,
    val lastSyncedAt: Instant?,
    val checksum: String?
)

data class AiIndexChunk(
    val sourceType: AiSourceType,
    val sourceKey: String,
    val chunkIndex: Int,
    val sourceContentHash: String,
    val sourceUpdatedAt: Instant,
    val startOffset: Int,
    val endOffsetExclusive: Int,
    val embedding: FloatArray,
    val modelId: String
)
```

约束：

- `DiaryEntry.date` 全局唯一，一天一篇正文。
- `AnnualSummary.year` 全局唯一，一年一篇年度总结。
- 正文以纯文本保存；历史 Markdown 内容可在阅读时兼容渲染，编辑时保留原文。
- 统计数据不单独持久化，优先由日记记录按需聚合生成。
- 本地数据库通过 SQLCipher 加密；SQLCipher passphrase 由用户应用密码通过固定公开 salt 与固定 KDF 参数确定性派生，应用密码同时用于云端内容加密。
- AI 索引使用独立文件 `tracediary_ai.db`，但必须与主数据库复用同一个 `deriveDatabasePassphrase(password)` 结果；禁止新增安装级随机 salt、随机 DEK、设备 ID、安装 ID 或仅存在于 Android Keystore 的恢复材料。
- AI 索引是可删除重建的派生数据，不同步云端、不进入导出备份；索引文件存在时可仅凭应用密码打开，文件丢失时从日记和年度总结重建。
- AI 索引只保存来源标识、分片范围、正文哈希、更新时间、固定模型版本和向量，不复制完整正文，不保存问题、回答或结构化事实缓存。
- 导入与导出文件保留明文（JSON / TXT ZIP / Markdown ZIP），便于跨平台备份；云端对象存储固定使用应用密码派生的密钥加密。
- "清空当日内容"等价于删除该日期的本地记录；启用云同步时同时删除对应远端对象，远端删除失败将记录待重试。

## 5.1 应用密码

TraceDiary 全局只保留一个"应用密码"，统一承担三个职责：

1. 应用解锁：冷启动或前后台切换满足锁定条件时需输入应用密码。
2. 本地数据加密：应用密码使用固定公开 salt 派生同一个 SQLCipher passphrase，用于主数据库和 AI 索引数据库；换设备或重新安装后，只要加密文件仍存在或已从备份恢复，知道应用密码即可重新打开。
3. 云端内容加密：应用密码使用固定公开 salt 派生 AES-256 key；每个云端对象正文用 AES-GCM 加密，密文自带随机 IV。

行为：

- 新安装首次启动必须设置应用密码；旧本地数据库与旧云端密文不做兼容迁移，升级到不兼容数据库格式时按"首版数据可丢弃"清库后再次要求设置密码。
- 默认在本机记住应用密码，可通过"数据加密"页关闭；本机缓存仅用于便利解锁，不参与数据可恢复性，关闭后冷启动必须输入密码。
- 修改应用密码为统一轮换：本地 SQLCipher 执行 rekey，并对云端对象用旧密码解密后用新密码重写；任一步骤失败则保留旧密码状态。
- 用户内容的解密能力只能依赖应用密码以及写入公开数据协议的固定 KDF 参数和公开常量；禁止依赖卸载后会丢失的本机秘密。AI 索引在改密时直接删除，并在主数据库换用新密码后重建。
- 普通设置、云存储 AK/SK、AI API Key、端侧模型文件和临时问答会话不属于可携带内容，卸载后允许重新配置或下载；不得让这些本机状态成为日记、年度总结或云端正文的解密前提。

## 6. AI 搜索

### 6.1 能力与数据边界

- AI 搜索支持当前解锁进程内的临时多轮追问，切换回顾子页时保留当前会话；问题、回答和依据不持久化。用户可通过“开始新会话”在二次确认后取消当前请求并清除问题草稿、回答、错误状态和 Agent 上下文；应用锁定或进程结束时同样清除会话。
- 日记正文和年度总结参与端侧语义索引；统计由本地确定性用例实时计算；提醒时间、日界线、每周首日和排序方式等普通偏好通过结构化工具读取。
- 应用密码、密码验证器、数据库 passphrase、云存储 AK/SK、AI API Key、Token、密文、Bucket、目录和内部同步元数据永久排除。
- 回答必须使用“根据你的记录”等证据限定表述；每项事实附来源日期或年份和真实原文片段，证据不足时明确返回不确定。
- 日记正文属于不可信数据，其中的指令不得改变系统提示、工具权限、日期范围或数据边界。

### 6.2 模型、索引与生命周期

- 首版端侧 Embedding 模型固定为 INT8 ONNX 版 `BAAI/bge-small-zh-v1.5`，输出 512 维 L2 归一化向量；短查询使用模型规定的中文检索指令，正文分片不附加指令。
- 模型文件固定且仅使用 ModelScope 镜像仓库 `Xenova/bge-small-zh-v1.5` 的固定 revision；禁止回退到 Hugging Face 上游或跟随 `master`、`main` 浮动版本。模型与词表分别下载到临时文件，逐文件校验固定大小和 SHA-256，只有两者全部通过后才原子启用；下载或校验失败时清理临时文件。首版不支持运行时切换或升级模型。
- 用户完成 AI 隐私说明和模型下载后，必须显式确认首次全量建索引；索引完整前禁止提问，不提供部分索引回答。
- 日记或年度总结新增、编辑、删除、导入或同步后，按正文哈希增量更新对应分片；应用解锁后检查并补齐未完成更新。
- 索引损坏、格式变化、密码修改或模型不匹配时只删除并重建 `tracediary_ai.db`，不得删除或破坏主日记数据库。

### 6.3 云端 Agent 与本地工具

- 用户自行配置 HTTPS Base URL、API Key 和模型名；接口采用 OpenAI Chat Completions 兼容格式，并提供 DeepSeek 默认预设。API Key 使用设备 Keystore 保护，卸载后重新填写。
- 保存配置前使用不包含用户数据的请求验证模型支持 Tool Calls 和结构化返回；验证失败不得启用 AI 搜索。
- 使用可取消的 SSE 只读工具循环，并限制工具调用次数、单次正文量、累计正文量和执行时间；提问后先执行一次端侧语义预检索，模型返回工具分片时继续执行工具，返回无工具正文时直接作为最终草稿流式展示，不再追加重复的正文生成请求。DeepSeek 官方模型使用低强度思考，并按官方 Tool Calls 协议仅在当前请求内存中完整回传各轮 `reasoning_content`；推理内容不得显示、写入临时会话或持久化。其他 OpenAI 兼容服务不发送供应商专用参数。
- Agent 只能调用以下只读工具：`semantic_search` 按来源与日期范围执行端侧向量检索；`list_records` 分页读取指定范围；`read_records` 读取指定来源原文；`get_statistics` 返回确定性统计；`get_preferences` 返回允许公开的普通偏好。
- “所有、哪些、一共”等穷举问题允许调用 `list_records` 扫描指定范围；只要 AI 搜索已开启且索引、云端配置与应用解锁状态满足门禁，Agent 即可在既有工具调用次数、正文量、日期范围和执行时间限制内直接进行大范围只读分析，不设置额外授权开关。
- 端侧记录实际提供给模型的日记、年度总结、统计和普通偏好来源，不再发起独立云端证据整理请求。最终来源必须在本地验证：来源仍存在，提供给模型的片段经 Unicode、空白和全角半角格式归一化后仍是当前原文的真实子串；单条无效来源直接丢弃，无任何有效来源时回答必须明确表达不确定。
- AI 搜索分为端侧语义预检索、流式只读工具循环和本地来源核对三个阶段。工具循环的候选正文首个分片立即展示，后续仅按屏幕帧合并真实增量；若同轮随后出现工具调用则撤回候选草稿并继续检索。SSE 不可用时仅对当前工具轮回退非流式接口，不增加额外安全模型或安全服务配置。

### 6.4 UI 与失败状态

- AI 搜索页覆盖未配置、模型未下载、模型下载中、索引未建立、索引构建中、可提问、等待回答、回答成功、可恢复错误和不可用状态。
- AI 搜索回答状态包含 Loading、Streaming、Validating、Answered、Failed 和 Cancelled；流式文字只显示未确认草稿，证据摘要只在 Answered 状态展示，取消、校验失败和应用锁定必须清除草稿。
- AI 搜索的问题和回答分别使用右侧浅主题色气泡与左侧浅色描边气泡；三个回顾子页的空状态共用同一图标尺寸、水平位置、顶部基准和文字间距。AI 空状态不展示问题示例，使用 AI 语义图标、标题和说明文字。
- 每轮回答气泡内部使用无点击反馈的“参考了 N 条资料”摘要行，右侧紧接向下尖角，不再显示“查看”；N 按所有有效来源去重。点击后打开标题为“N 条资料”、最高约占屏幕 70% 的底部资料面板，条目只显示来源、最多两行原文和可跳转箭头，并以细分隔线分隔；无有效资料时显示不可点击的“未找到可核对的资料”。资料面板保留无 Tooltip / hover 高亮的拖动手柄和拖动能力。
- 普通搜索与 AI 搜索输入框统一使用 12 dp 圆角、白色背景、细边框、零阴影和一致的高度基准；普通搜索保留单行即时筛选和搜索图标，AI 搜索保留多行输入、新会话、提交和中断操作。
- 输入、用户问题和 AI 回答气泡统一圆角、边框、内边距和无阴影视觉，仅通过颜色区分；点击发送后立即清空输入框并新增用户问题气泡和 AI 回答 Loading 气泡。Loading 气泡显示由真实执行事件驱动的单行状态，包括理解问题、搜索记录、浏览范围、读取记录、整理统计、读取设置、生成回答和核对资料，不展示模型思维过程、内部工具名或正文；请求期间发送按钮原位切换为黑色圆形内的方形 Stop 图标，取消后停止动画并在回答气泡中显示已取消状态，不再使用回答区域外的独立取消按钮。
- 设置外部入口名为“AI 搜索”，页面标题为“AI搜索设置”；页面自上而下展示“AI搜索”开关、“端侧模型与加密索引”和“云端大模型”。端侧区域不展示模型名称：索引未建立时提供带下载大小的模型下载按钮和索引建立按钮；索引已建立时将“重建索引”和“清理索引”等宽并排，清理按钮位于右侧且必须二次确认。云端区域使用与同步设置一致的行内输入样式，字段顺序固定为 Base URL、API Key、模型名，并提供保存与连接验证。
- AI 搜索与同步设置的连接配置均使用“保存并验证”交互：验证期间显示可取消的统一进度对话框，成功或失败显示统一结果对话框；连接验证成功后才持久化当前配置，失败或取消只保留页面草稿，不覆盖已生效配置。AI 使用 Tool Calls 验证，同步使用对象存储 `ping` 验证。
- 设置体系的选择、确认、进度和结果对话框统一使用同一视觉外壳：14 dp 圆角、最大 320 dp 响应式宽度、一致的标题/正文/按钮间距；破坏性确认使用错误色。场景组件保持各自交互语义，不用选项列表替代进度或结果内容。
- 用户可随时取消下载、索引或 Agent 请求；认证失败、限流、超时、断网、模型不兼容、非法响应、应用锁定和证据验证失败必须展示可理解的产品化错误，不泄露原始请求、密钥或日记正文。
- 证据来源可跳转对应日记或年度总结；没有网络时保留关键词搜索入口，不把 AI 错误伪装为“未找到记录”。

### 6.5 安全与性能验收

- 应用锁定时立即取消 Agent 与索引任务、关闭 AI 数据库、释放模型推理会话并清除问题、候选正文和回答；每次本地工具调用前重新检查解锁状态。
- 正式版本只允许 HTTPS Agent Base URL；AI 性能诊断以单次提问的短关联 ID 聚合，只允许记录阶段名、耗时、HTTP 状态、请求/响应字符数、消息/工具数量、推理/正文事件数量、工具白名单类型计数、重试/回退次数和结果类别。日志、崩溃报告和分析事件不得记录 API Key、问题全文、模型推理内容、候选正文、回答正文、证据片段、来源标识、Base URL、模型名、工具参数、工具结果或异常原文；本地诊断字段不得序列化进云端请求。
- 首要性能验收设备为 OPPO Find X9 Pro 16 GB：模型下载资产不超过 100 MB；冷加载不超过 3 秒；单条查询向量生成 P95 不超过 1 秒；1000 篇、每篇约 500 个中文字符的测试集在 5 分钟内完成首次索引；AI 过程额外峰值内存不超过 512 MB。
- 真机验收还必须覆盖模型下载中断、索引取消续建、前后台切换、应用锁定、网络切换、连续追问、长答案滚动和证据跳转；不得出现明显卡顿、崩溃或持续异常发热。

## 7. 测试策略（强制）

本项目采用分层测试策略。所有开发任务都必须按风险和改动范围执行相应测试；不得仅凭“真机看起来正常”代替基础自动化验证。

### 7.1 测试层次

#### 7.1.1 本地单元测试

适用于纯 Kotlin 逻辑，不依赖 Android 设备或模拟器：

- 日期计算、周日历与月份切换逻辑
- 搜索过滤与排序逻辑
- AI 正文分片、WordPiece 分词、CLS pooling、向量归一化、余弦排序、日期范围和索引失效逻辑
- Agent 工具参数校验、调用上限、证据验证、临时会话和大范围只读分析逻辑
- 连续记录、月度趋势、年度热力图等统计聚合逻辑
- Domain UseCase 与同步状态转换逻辑
- 导入导出解析、序列化、校验逻辑

要求：

- 目录：`app/src/test/`
- 默认命令：`./gradlew test`
- 新增纯业务逻辑时，优先补单元测试，而不是把逻辑埋进 Compose 页面中再依赖人工验证

#### 7.1.2 数据层测试

适用于 Room、DataStore、Repository、本地加密存储与导入导出实现：

- `DiaryEntry.date` 一天一篇的唯一性约束
- `AnnualSummary.year` 一年一篇的唯一性约束
- DAO 查询、插入、更新、删除行为
- Repository 对本地数据库与同步元数据的读写封装
- DataStore 设置项读写
- AI 索引数据库加密、同密码恢复、错误密码拒绝、增量更新、删除和可重建行为
- 导入后本地落盘结果与导出文件结构

要求：

- 涉及数据结构、唯一性约束、数据库迁移、导入导出时必须补对应测试
- 任何会影响数据正确性与持久化的改动，不得只依赖 UI 操作验证

#### 7.1.3 ViewModel / UseCase 测试

适用于页面状态、用户动作与业务流程：

- 今天页加载日期、切换日期、自动保存状态更新、周/月历切换、清空当日内容（含云端删除失败兜底）
- 年度总结切换年份后的状态加载与保存
- 搜索页筛选条件组合
- AI 配置、模型下载、完整索引门禁、临时多轮问答、取消、锁定和错误恢复
- 同步成功、失败、等待中的状态切换
- 应用密码首次设置、解锁、错误密码、修改密码（含云端 rekey 成功/失败回滚）
- 设置页开关、偏好项、提醒项的状态流转

要求：

- ViewModel 中存在条件分支、异步状态、错误恢复、保存状态提示时，必须补测试
- 不允许把复杂状态判断只放在 UI 层而没有对应状态测试

#### 7.1.4 Compose UI 测试

适用于 Compose 页面与组件交互：

- 底部导航切换：今天 / 回顾 / 统计 / 设置
- 回顾页二级文字 Tab 切换：AI搜索 / 搜索 / 年度总结，默认 AI搜索
- AI 未配置、模型下载、索引进度、临时会话、开始新会话、依据摘要与底部面板、大范围分析和错误状态
- 输入框、按钮、空状态、错误状态、加载状态
- 列表项点击、年份选择、保存状态文案显示
- 今天页周历展开为月历、月份文字跳转、底部导航重复点击返回当天、编辑卡片清空入口、有记录标记
- 应用解锁页：首次设置密码、错误密码提示、解锁后进入主界面

要求：

- 目录：`app/src/androidTest/`
- 适用于关键交互路径和高风险 UI 状态
- 不要求每个像素都写 UI 测试，但关键页面至少应有可回归的交互覆盖

#### 7.1.5 真机验收测试

本项目首要目标设备为 OPPO / ColorOS 手机，真机验收属于必选项，不是附加项：

- 键盘弹起后编辑区是否被遮挡
- 系统返回手势、前后台切换、锁屏恢复
- 自动保存提示、同步状态提示是否自然
- 大段中文输入是否流畅
- 文件导入导出权限是否可用
- WorkManager、提醒、后台同步在真机上的行为
- 端侧模型冷加载、批量索引、内存与发热、Agent 网络切换、锁定取消和证据跳转

要求：

- 任何影响编辑体验、系统交互、权限、后台任务的改动，都必须至少在真机上验证一次
- 模拟器通过不能替代真机验收

#### 7.1.6 视觉与设计验收

本项目 UI 必须与参考图保持同一产品气质：

- `reference/today.png`
- `reference/review-search.png`
- `reference/review-year-summary.png`
- `reference/stats.png`
- `reference/settings.png`

验收点：

- 布局层级、边距、圆角、阴影、信息密度是否一致
- 文本是否溢出、截断异常、换行失控
- 选中态、禁用态、空状态是否符合当前设计风格
- 不得出现明显偏离 OPPO / ColorOS 工具类应用气质的 UI

### 7.2 默认测试命令

- 单元测试：`./gradlew test`
- 调试包构建：`./gradlew assembleDebug`
- 设备 / 模拟器 UI 测试：`./gradlew connectedAndroidTest`

说明：

- 若当前环境不便直接跑 `connectedAndroidTest`，必须明确说明，并由真机人工验收补位

### 7.3 风险分级与最低执行标准

#### 7.3.1 低风险改动

范围：

- 纯文档
- 文案微调
- 不影响逻辑的资源替换

最低要求：

- 可不执行自动化测试
- 最终汇报必须注明“仅文档/资源改动，无功能行为变化”

#### 7.3.2 中风险改动

范围：

- 单页面 UI 调整
- ViewModel 状态变更
- 搜索、统计、日期切换等单模块逻辑
- 设置页普通配置项

最低要求：

- `./gradlew test`
- `./gradlew assembleDebug`
- 至少一次真机验收

#### 7.3.3 高风险改动

范围：

- 数据库结构、唯一性约束、迁移
- 导入导出
- 加密、解密、密钥管理（含应用密码、SQLCipher passphrase 派生、云端 rekey）
- 云同步、备份、恢复（含单条远端删除与待重试记录）
- WorkManager、提醒、后台任务
- AI 模型下载与端侧推理、加密索引、云端 Agent、敏感正文外发和证据校验

最低要求：

- `./gradlew test`
- `./gradlew assembleDebug`
- 相关数据层/状态层测试补齐
- 至少一次真机验收
- 涉及关键交互时补 `connectedAndroidTest` 或等价 UI 回归

### 7.4 提交流程要求

- 每完成一个可独立验收的开发任务，提交前必须说明已执行的测试项与未执行项
- 若某项测试未执行，必须说明原因与风险，不得省略
- 影响主记录链路（今天页编辑、自动保存、数据落盘、导入导出、同步）的任务，不得跳过基础自动化测试
- 新增 bug 修复时，优先补能复现并防回归的测试

### 7.5 与当前开发方式的适配

本项目采用“Codex 编码 + 开发机构建 + 用户真机验收”的协作方式，默认流程如下：

1. Codex 实现功能或修复问题
2. 运行 `./gradlew test`
3. 运行 `./gradlew assembleDebug`
4. 安装到真机或通过 Android Studio 运行到 OPPO 设备
5. 对照参考图和真实交互进行人工验收
6. 测试通过后再提交与推送

该流程为默认要求；除非是纯文档改动，否则不应省略第 2 至第 5 步。
