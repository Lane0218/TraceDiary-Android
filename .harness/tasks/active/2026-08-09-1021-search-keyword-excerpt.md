# 搜索结果卡片围绕关键词展示摘要并高亮
状态=计划中
更新时间=2026-08-09 10:21

## 目标与背景

- 修正搜索结果卡片固定展示正文开头 60 个字符的问题，使摘要围绕实际命中的关键词提供前后文。
- 在摘要中突出显示关键词，让用户无需打开整篇日记即可判断结果是否包含目标信息。
- 当前搜索能够匹配正文任意位置，但卡片先截取正文开头再尝试高亮；关键词位于后文时，摘要与命中位置无关且高亮不可见。

## 范围

- 仅调整回顾页搜索结果卡片的摘要生成与关键词高亮。
- 保持现有关键词匹配、年份筛选、排序、结果卡片点击跳转日期等行为不变。
- 不实现点击结果后在“今天”编辑页自动滚动、选中或高亮关键词。
- 不修改 Room、DAO、Repository、日记数据结构、同步协议或加密逻辑。
- 实施时将稳定的搜索结果摘要行为同步到 `.harness/spec/SPEC.md`。
- 风险等级：中；主要风险是摘要边界截断错误、关键词与高亮范围错位、Unicode 字符被截断，以及防抖期间用新关键词渲染旧结果。

## 验收标准

- 关键词位于正文开头 60 个字符之后时，结果卡片仍展示包含完整关键词的摘要。
- 摘要在内容允许时同时保留关键词前后文；省略正文开头或结尾时，仅在对应一侧显示省略号。
- 摘要内所有可见的关键词命中均使用主题主色并加粗，匹配保持现有英文大小写不敏感语义并保留正文原始字符。
- 摘要截取以 Unicode 代码点为边界，不拆分 emoji 等代理对；关键词较长时优先完整保留关键词而不是强行满足默认摘要长度。
- 正文换行和连续空白在卡片中折叠为单个空格，折叠后高亮范围仍与显示文本一致。
- 搜索输入防抖期间，卡片摘要使用与当前结果列表一致的已应用关键词，不出现新关键词高亮旧结果的短暂错配。
- 关键词位于开头、正文中部、结尾，多次出现，包含中文、英文大小写、换行及 emoji 时均有 JVM 单元测试覆盖。
- 现有搜索筛选、日期倒序和点击结果跳转对应日期的行为无回归。
- Windows 环境执行 `gradlew.bat test` 与 `gradlew.bat assembleDebug` 通过。
- OPPO / ColorOS 真机确认摘要不超过合理信息密度、关键词清晰可辨且卡片无异常换行或截断；用户确认前任务状态保持“待验收”。

## 实施步骤

1. 在 SPEC 的“回顾-搜索”功能与视觉验收要求中补充关键词上下文摘要和高亮规则。
2. 在 `ui/review` 抽取无 Compose 渲染依赖的纯 Kotlin 摘要模型与生成函数，输出显示文本及 `start/endExclusive` 高亮范围；初始参数采用最多约 72 个 Unicode 字符、关键词前约 28 个字符，并以真机信息密度验收结果微调。
3. 摘要生成时先统一卡片展示所需的空白，再定位首个大小写不敏感命中；围绕首个命中选取窗口、补充两侧省略号，并收集窗口内全部命中范围。
4. 在 `SearchUiState` 记录结果对应的已应用关键词，确保防抖更新时结果与摘要查询快照原子一致。
5. 将结果卡片摘要渲染拆为独立组件，通过 `AnnotatedString` 对命中范围应用主题主色与粗体；使用稳定键记忆纯函数结果，避免无关重组重复计算。
6. 补摘要纯函数、ViewModel 查询快照及搜索结果卡片回归测试，执行规定的 Windows 构建与测试。
7. 完成真机视觉验收后更新验证结果、归档任务，并按项目 Git 规则将 Harness 与产品代码分别提交、推送。
